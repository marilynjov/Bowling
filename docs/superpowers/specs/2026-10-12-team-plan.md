# Team Plan: Two Developers

Date: 2026-10-12
Status: draft, pending review
Roadmap: `2026-10-07-program-roadmap.md`

## Roles

- **Frontend developer**: everything the user sees and touches.
- **Data and AI developer**: the domain model, engines, persistence, sync, backend, and AI
  integrations, plus feature development where the frontend load is heavier.

The architecture already separates the two. The app target holds only views, feature
models, and navigation; the packages hold every engine and all persistence. Each role
owns one side.

## Ownership

| | Frontend developer | Data and AI developer |
|---|---|---|
| Code | `Bowling/` app target: `Features/`, `Components/`, navigation | `Packages/`: BowlingCore, BowlingData, and the logic in ScanKit, LeagueKit, PracticeKit, and SocialKit |
| Owns | Look and feel, the pin deck, charts, accessibility, the String Catalog, UI tests and previews, TestFlight sessions with bowlers | The schema and its rules (critical before phase 2 locks it), scoring, leave classification, stats, sync, backend, AI integrations, reference data licensing |
| Reviews | Every PR that changes what the screens receive | Every PR that touches persistence or stats |

## The contract between the two sides

The app target talks to the packages only through the BowlingCore value types
(`PinSet`, `RollRecord`, `FrameRecord`, `GameRecord`), the repository methods,
`StatsReport`, `BallReport`, and the stats card IDs. The first week of phase 1a agrees
this contract and the demo fixture data, so the frontend developer builds screens
against fixtures while the engines are written.

Rule: any change to the contract goes in a PR that both developers review.

## Schedule

- Phases do not take half the time; coordination has a cost. Phases can overlap: the
  data and AI developer can start the next phase's engine or backend while the frontend
  developer finishes the current phase's screens. For example, the phase 4 scan pipeline
  can start during phase 3.
- Initial guess: 35 to 40 percent less total calendar time than the roadmap's time
  boxes. Recalibrate after phase 1a, as the roadmap's working rhythm requires.
- The data and AI developer carries more work. In phase 1a the frontend developer also
  owns UI tests and preview fixtures; "feature development" in the data role covers the
  remaining gaps.

## Workflow

- One feature branch per GitHub issue, each issue labeled `owner:frontend` or
  `owner:data`, in the phase's milestone.
- The other developer reviews every PR. `main` always builds.
- A short weekly check-in on contract changes and blockers.
- Each phase's spec is written by both: the data and AI developer drafts the model and
  engine sections, the frontend developer drafts the screens.

## Accounts and tools

- **Apple Developer Program**: one membership for the team. Both developers must be on
  the developer team to sign builds and use the app's iCloud container on a device. An
  Individual membership cannot add developers to the team, so enroll as an
  Organization (needs a legal entity and a free D-U-N-S number), or have the account
  holder manage signing. Confirm the current rules with Apple before enrolling.
- **Sentry**: the free Developer plan has one user. The data and AI developer is that
  user and triages crashes; move to the Team plan (about $26 per month) only if both need
  access.
- **Supabase**: the development instance runs on the data and AI developer's PC.
- **GitHub**: both developers are collaborators on the repository and the project board.

# App Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the template app with the shell from #4: store loading, first-launch
gate, four tabs with placeholder screens, Settings, a Scoring cover, a shared error
alert, and a Liquid Glass modifier.

**Architecture:** `AppModel` (`@Observable`) wraps Santiago's `BowlingStore`; every write
goes through `app.write`, which bumps `revision`, and screens reload in
`.task(id: app.revision)`. `RootView` picks onboarding or tabs and owns the one Scoring
`.fullScreenCover` and the error alert. Placeholders each read one real value so the
data path is proven before #6 to #13 build the real screens.

**Tech Stack:** SwiftUI, Observation, Swift Testing, BowlingData and BowlingCore
(local packages), Xcode 27, iOS 18.0 minimum.

**Spec:** `docs/superpowers/specs/2026-10-14-app-shell-design.md` (read it first), and
`docs/superpowers/specs/2026-10-07-phase-1-core-scoring-design.md` section 7.

## Global Constraints

- iOS deployment target 18.0; anything newer goes behind `if #available`.
- The app target uses `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` and
  `MEMBER_IMPORT_VISIBILITY`: import every module whose types a file uses
  (`BowlingCore` for `BowlerID`, `EventType`, ...), and no `@MainActor` annotations are
  needed in the app target.
- The app talks to packages only through the contract: repositories, value types, error
  types. Never import SwiftData in `Bowling/`.
- No third-party dependencies.
- `BowlingFixtures` and `BowlingStore.demo()` are used only inside `#if DEBUG`.
- Branch `feat/4-app-shell`. marilynjov makes the commits: at each commit step, show the
  commit message and the staged files, and let them commit. End messages with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Build command (AGENTS.md):
  `xcodebuild -scheme Bowling -destination 'platform=iOS Simulator,name=iPhone 18 Pro' build`
- Test command: same with `test` instead of `build`.

## Review Focus

1. **Delete all data while the app is open** (Settings, #13): the root must fall back to
   onboarding. Test `needsOnboardingAfterDeleteAllData` in Task 1.
2. **Double tap on onboarding's Continue:** the second `createOwner` throws
   `.ownerAlreadyExists` after the root has already switched. Expected: no alert. Task 3
   disables the button after the first tap; verify by hand.
3. **Closing the Scoring cover before any roll:** spec §8 says the session is deleted.
   The placeholder calls `discardIfUnstarted` on close. Test
   `startThenCloseLeavesNoSession` in Task 4.
4. **The store fails to open:** Retry must try again and succeed once the cause is gone,
   never fall back to an empty store. Test `retryAfterFailureOpens` in Task 2.
5. **An error that is not a `RepositoryError`** (a SwiftData save failure) must still
   show readable text, not a blank alert. Test `otherErrorsUseTheirDescription` in
   Task 1.

- [ ] **Step 3: Implement `AppModel` and `ErrorText`**

  `needsOnboarding` reads `revision` before calling `store.bowlers.owner()`, so
  Observation re-evaluates it after every write. `write` bumps `revision` in a `defer`.

  Error copy (exact):

  | Error | Text |
  |---|---|
  | `.notFound` | That item no longer exists. It may have been deleted. |
  | `.invalidGame` | That roll doesn't fit this frame. |
  | `.entryModeLocked` | The entry mode can't change after the first roll. Clear the game's rolls first. |
  | `.bowlerHasGames(count:)` | see Step 2 |
  | `.cannotDeleteOwner` | You can't delete your own profile. |
  | `.ownerAlreadyExists` | Your profile already exists. |
  | `.invalidBall(.emptyName)` | Give the ball a name. |
  | `.invalidBall(.weightOutOfRange)` | Ball weight must be 6 to 16 pounds. |
  | `.invalidBowler(.emptyName)` | Enter a name. |
  | `.notFinalOnly` | This game is scored from its rolls, so its score can't be typed. |
  | anything else | `error.localizedDescription` |

  Use `String(localized:)` for each so they are ready for localization (spec §10).

### Task 4: Scoring cover and Liquid Glass

**Files:**

- Produces: `extension View { func glassBackground(in shape: some Shape) -> some View }`;
  `AppModel.startPracticeSession() throws` and `AppModel.closeScoring()`, used by Home's

- [ ] **Step 1: Write the failing tests**

  On an in-memory store with an owner:

    is in `store.sessions.sessions()` with event type `.practice`, and its `gameID` is
    the owner's game 1.

    `closeScoring()`, `scoring == nil` and `sessions()` is empty.

- [ ] **Step 2: Run them to verify they fail**

  Expected: compile failure, `startPracticeSession` not defined.

- [ ] **Step 3: Implement**

  - `startPracticeSession()`: one `write` calling `startSession(SessionMetadata(date:
    .now, eventType: .practice), bowlers: [(owner.id, nil)], entryMode: .pinByPin)`,

  - `HomeScreen`: a "Start" button calling `startPracticeSession()`, errors to

# UI Test: Full Pin-by-Pin Game Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One XCUITest drives a full pin-by-pin game through the real controls and checks the summary shows 193.

**Architecture:** A Debug-only `UITestLaunch` turns the `-uiTesting` launch argument into an in-memory store seeded with owner Sam and a cleared UserDefaults suite, handed to `StoreLoader`. Accessibility identifiers go on the seven controls the test touches. A unit test drives `ScoringModel` with the same inputs so the expected 193 is checked without the simulator UI.

**Tech Stack:** SwiftUI iOS 18, Swift 6 (MainActor default isolation in the app and unit tests), Swift Testing for unit tests, XCTest/XCUITest for `BowlingUITests`.

**Spec:** `docs/superpowers/specs/2026-10-29-ui-test-design.md`

## Global Constraints

- Never edit `Packages/` (SantiagoM99's). Use only the contract: `BowlingStore(inMemory:)`, `store.bowlers.createOwner(name:handedness:statsProfile:)`.
- The launch mode exists only under `#if DEBUG`; a Release build must compile without it.
- A launch without `-uiTesting` is unchanged: `BowlingStore()` and `UserDefaults.standard`.
- VoiceOver labels and traits do not change; only `.accessibilityIdentifier` is added.
- Identifiers, verbatim: `home.startSession`, `newSession.start`, `pin.1` … `pin.10`, `scoring.next`, `scoring.strike`, `scoring.spare`, `scoring.miss`, `summary.score`.
- Seeded owner: name "Sam", handedness `.right`, stats profile `.league`.
- Commits have no Co-Authored-By trailer.
- Unit test command: `xcodebuild test -scheme Bowling -destination 'id=2C568C51-3721-4FB2-90EE-D54EB3308C03' -parallel-testing-enabled NO -only-testing:BowlingTests/<Suite>`. On "Failed to create a bundle instance", rerun. UI test: same with `-only-testing:BowlingUITests/PinByPinGameUITests`. Never use the "iPhone 18 Pro" named destination locally.

## Review Focus

1. A Release build still compiles (no `UITestLaunch` reference outside `#if DEBUG`). Task 1 Step 6 builds Release.
2. A second UI-test run starts clean: whatever the previous run left in the suite is gone. Task 1 test `defaultsStartEmpty`.
3. A normal launch keeps `.standard` defaults. Task 1 test `loadUsesTheGivenDefaults` plus the untouched default parameter.
4. The summary sheet opens after an animation; the test waits (`waitForExistence(timeout: 10)`) rather than reading immediately. Task 2 test.
5. Pin taps go through the deck's `DragGesture`, not the accessibility action: `XCUIElement.tap()` touches the pin's centre, which is what a person does. If a tap lands but marks nothing, the next `Next` records a strike and the score is wrong, so the 193 assertion catches it.

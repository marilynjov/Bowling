# Settings 1a Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Settings screen: profile, bowling style, default games, the three scoring
toggles, an iCloud placeholder, About, and Delete all data with double confirmation.

**Architecture:** Pure value types (`SettingsRows`, `ProfileDraft`) turn the owner into row
text and choices and are unit tested; `AppModel.deleteAllData()` owns the wipe and the
reset of on-device and in-memory state. Views only render and write through `app.write`.

**Tech Stack:** SwiftUI (iOS 18, `@Observable`, MainActor default isolation), Swift Testing,
BowlingCore/BowlingData contract.

**Spec:** `docs/superpowers/specs/2026-10-28-settings-design.md`

## Global Constraints

- The app talks to packages only through the contract (AGENTS.md). No package edits;
  `Packages/` is Santiago's.
- Copy is fixed by the spec: "Settings", "Profile", "Save", "Bowling style", "Casual",
  "League", "Competitive", "Decides which stats you see first.", "Default games", "Follow
  bowling style (Competition)", "Follow bowling style (All games)", "Competition", "All
  games", "Where Stats and Home start. You can still change it on Stats.", "Pin entry",
  "Tap standing", "Tap what fell", "Auto-advance on spares", "Records the second ball once
  it makes a spare.", "Rotate bowlers", "Each night starts with this. You can still switch
  it in Scoring.", "iCloud sync", "Coming soon", "Version", "Delete all data", "Delete all
  data?", "This deletes every session, game, ball and your profile from this iPhone.",
  "This can't be undone.", "Delete everything", "Name", "Hand", "Left", "Right";
  profile summary "Sam · Right-handed" / "Sam · Left-handed" / "Sam".
- Bowling style and default games save as soon as they are picked; the scoring toggles
  stay in `ScoringSettings` (UserDefaults, never synced).
- Every write goes through `app.write`; a thrown error goes to `app.error` (shared alert).
- Each screen has Light, Dark and AX5 previews.
- Test command (never the iPhone 18 Pro named destination):
  `xcodebuild test -scheme Bowling -destination 'id=2C568C51-3721-4FB2-90EE-D54EB3308C03' -parallel-testing-enabled NO -only-testing:BowlingTests/<Suite> > .superpowers/sdd/2026-10-28-settings/<suite>.log 2>&1`, then grep the log for `✘|Test run with|TEST (SUCC|FAIL)`.
  A suite filter names one `@Suite` struct. The simulator sometimes fails with "Failed to
  create a bundle instance": rerun. If xcodebuild hangs after the tests finish, kill it by
  PID from `pgrep -x xcodebuild`, never `pkill -f`.
- Commits: no `Co-Authored-By` trailer.
- New app files in `Bowling/Features/Settings/`, new tests in `BowlingTests/Settings/`
  (synchronized folders, no pbxproj edits).

## Review Focus

1. A name of only spaces must not save (the owner would be renamed to nothing). Task 2
   tests `canSave` with "   ".
2. A hand or style written by a newer app version (`.unknown`) must not be overwritten by
   opening and saving Profile or by viewing Settings. Task 2 tests the draft's nil hand
   saves `.unknown` and `SettingsRows` shows no style.
3. After Delete all data and a new first launch, Stats must not start from the old
   bowler's filter, and Home must not offer the old quick score undo. Task 1 tests
   `statsFilter` and `savedQuickScore` are nil.
4. A failed delete must leave the phone's settings alone (the user still has their data
   and their preferences). Task 1 implements reset-after-success; the reviewer checks the
   order.
5. Changing the bowling style while a Stats filter is untouched moves Stats' default too.
   Task 2's behavior test goes through `StatsFilterDraft.current(nil, in:)`.

### Task 2: SettingsRows, ProfileDraft and the Done-when tests

**Files:**
- Create: `Bowling/Features/Settings/SettingsRows.swift`, `Bowling/Features/Settings/ProfileDraft.swift`
- Test: `BowlingTests/Settings/SettingsRowsTests.swift`, `BowlingTests/Settings/ProfileDraftTests.swift`, `BowlingTests/Settings/SettingsBehaviorTests.swift`

**Interfaces:**
- Produces:
  ```swift
  struct SettingsRows: Hashable {
      enum DefaultGames: Hashable, CaseIterable {
          case follow, competition, allGames
          var scope: StatsScope? { get }        // nil, .competition, .all
      }
      static let styles: [StatsProfile]         // [.casual, .league, .competitive]
      var profileSummary: String                // "Sam · Right-handed"
      var style: StatsProfile?                  // nil for .unknown
      var defaultGames: DefaultGames            // nil and .unknown scope read as .follow
      init(owner: BowlerRecord)
      func title(_ games: DefaultGames) -> String   // follow: "Follow bowling style (Competition)" from prefersCompetition(owner.statsProfile)
      static func title(_ style: StatsProfile) -> String  // "Casual", "League", "Competitive"
  }
  struct ProfileDraft: Hashable {
      var name: String
      var handedness: Handedness?               // nil for .unknown
      init(owner: BowlerRecord)
      var canSave: Bool                         // name not blank after trimming
      /// Passes `.unknown` for a nil hand, which keeps the stored one.
      func save(to bowlers: BowlerRepository) throws
  }
  ```

- [ ] **Step 1: Write the failing tests** (in-memory store; owner via `createOwner`, games as in
  `StatsFilterDraftTests.game(_:for:)`).
  - `SettingsRowsTests`:
    - `profileSummaryNamesTheHand`: right → "Sam · Right-handed"; left → "Sam · Left-handed";
      a `BowlerRecord` copy with `handedness = .unknown` → "Sam".
    - `followNamesWhatTheStylePicks`: league owner → `title(.follow) == "Follow bowling style (Competition)"`;
      casual → "Follow bowling style (All games)"; `title(.competition) == "Competition"`, `title(.allGames) == "All games"`.
    - `defaultGamesFromTheScope`: `statsScope` nil → `.follow`, `.competition`, `.all` → `.allGames`, `.unknown` → `.follow`;
      `DefaultGames.allCases.map(\.scope) == [nil, .competition, .all]`.
    - `styleFromTheProfile`: league → `.league`; a copy with `.unknown` → nil; `styles.map(SettingsRows.title) == ["Casual", "League", "Competitive"]`.
  - `ProfileDraftTests`:
    - `blankNameCantSave`: name "" and "   " → `!canSave`; "Ana" → `canSave`.
    - `saveRenamesAndSetsTheHand`: draft from Sam (right), name " Ana ", hand `.left`, save →
      `owner()?.name == "Ana"`, `.handedness == .left`.
    - `unknownHandStartsUnpicked`: draft from a record copy with `.unknown` → `handedness == nil`, and with a name `canSave`.
  - `SettingsBehaviorTests` (the Done-when):
    - `bowlingStyleChangesTheCards`: league owner; `setStatsProfile(.casual)` →
      `HomeData.load(from:).tiles.map(\.card) == StatsPreset.homeTiles(for: .casual)` and
      `StatsPreset.displayedStatsCards(layout: owner.statsLayout, profile: owner.statsProfile) == StatsPreset.statsCards(for: .casual)`.
    - `defaultGamesChangesWhereStatsStarts`: league owner with one league game;
      `StatsFilterDraft.current(nil, in:)?.scope == .competition`; then
      `setStatsScope(SettingsRows.DefaultGames.allGames.scope)` → `.allGames`, and
      `SettingsRows(owner:).defaultGames == .allGames`.
    - `followingTheStyleAgainRestoresIt`: after `.allGames`, `setStatsScope(DefaultGames.follow.scope)` → `.competition`.
- [ ] **Step 2: Run** `-only-testing:BowlingTests/SettingsRowsTests -only-testing:BowlingTests/ProfileDraftTests -only-testing:BowlingTests/SettingsBehaviorTests`.
  Expected: build fails on `SettingsRows` / `ProfileDraft`.

### Task 3: The Settings screens

**Files:**
- Modify: `Bowling/Features/Settings/SettingsScreen.swift` (replace the placeholder)
- Create: `Bowling/Features/Settings/ProfileScreen.swift`

**Interfaces:**
- Consumes: Tasks 1 and 2.
- Produces (views only):
  - `SettingsScreen`: `Form` titled "Settings", sections per spec §1. `@State var rows: SettingsRows?`
    reloaded in `.task(id: app.revision)` from `app.store.bowlers.owner()`; the Form is always
    rendered so the task runs. Style and default-games pickers write through
    `app.write { try $0.bowlers.setStatsProfile(_) }` / `setStatsScope(choice.scope)`, catching into
    `app.error`. Pin entry is a `Picker` bound to `app.scoringSettings.tapWhatFell` through a
    local `@State` mirror (UserDefaults isn't observable); the auto-advance row shows only when it is
    true. Version reads `Bundle.main` `CFBundleShortVersionString` and `CFBundleVersion` → "1.0 (12)".
    Delete: a `confirmationDialog` then an `.alert`, then `try app.deleteAllData()` catching into `app.error`.
  - `ProfileScreen`: pushed with `NavigationLink`; `@State var draft: ProfileDraft`; Name
    `TextField`, Hand segmented `Picker` over `Handedness?` (Left, Right); toolbar Save disabled
    unless `draft.canSave`; Save → `app.write { try draft.save(to: $0.bowlers) }`, then `dismiss()`;
    on error set `app.error` and stay.

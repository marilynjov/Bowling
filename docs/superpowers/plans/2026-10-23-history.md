# History Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The History tab: sessions by month, session detail, game detail, Edit into
Scoring, swipe to delete, and the session details form, plus the Next game fixes from
Santiago's #101 review.

**Architecture:** Pure value types (`HistoryList`, `SessionDetailData`, `GameDetailData`,
`DeleteRequest`) are built from the repositories and unit tested; the views only render
them. Navigation is a `[HistoryRoute]` path on `AppModel`, so Home can open a session and
deletes can pop routes. `SessionDetailsDraft` is pulled out of `NewSessionDraft` so New
session and the details form share one set of rules.

**Tech Stack:** SwiftUI (iOS 18, `@Observable`, MainActor default isolation), Swift
Testing, BowlingCore/BowlingData contract.

**Spec:** `docs/superpowers/specs/2026-10-23-history-design.md`

## Global Constraints

- The app talks to packages only through the contract (AGENTS.md). No package edits on
  this branch; `Packages/` is Santiago's.
- Every write goes through `app.write`; failures go to `app.error` and the topmost
  screen's `sharedErrorAlert`.
- Copy is fixed by the spec: "October 2026", "3 bowlers", "In progress", "Delete this
  session? Its N games will be deleted." ("1 game" for one), "Delete Alex's game 2?",
  "Delete this session? It has no other games.", "Series 590", "Game 2", "Game 2 · Alex",
  "Enter pins to see leaves.", "Default · Phaze", "Hammer · frames 3 and 7",
  "Deleted ball", "Your sessions show up here.", "This session was deleted.",
  "This game was deleted.".
- VoiceOver strings live in `AccessibilityText` and are unit tested: "October 21, League,
  AMF Bowl, Tuesday Mixed, 3 bowlers, 201, 189, 224, in progress"; "Alex, series 590";
  "Game 2, 189"; "Hammer, frames 3 and 7".
- Each screen has Light, Dark and AX5 previews.
- Test command (never the iPhone 18 Pro simulator):
  `xcodebuild test -scheme Bowling -destination 'id=2C568C51-3721-4FB2-90EE-D54EB3308C03' -parallel-testing-enabled NO -only-testing:BowlingTests/<Suite> > .superpowers/sdd/2026-10-23-history/<suite>.log 2>&1; tail -40 <log>`.
  If xcodebuild hangs after "Test Suite ... passed", kill it by PID from
  `pgrep -x xcodebuild`, never `pkill -f`.
- Commits: the user commits and pushes. Each commit step gives the exact `git add` and
  `git commit -m` lines; no `Co-Authored-By` trailer.
- New test files go in `BowlingTests/History/`; new app files in `Bowling/Features/History/`
  (synchronized folders, no pbxproj edits).

## Review Focus

1. Closing Scoring opened from History must never delete the session. `closeScoring`
   calls `discardIfUnstarted`; an old session whose only game had Clear rolls would be
   deleted. Task 3 pins it: a `startsOnTarget` target is never discarded.
2. An uneven night (one bowler's latest game deleted): the latest game number, Next game
   and the summary cards must follow each bowler's own game, not one shared `gameIndex`.
   Tasks 4 and 6 test it.
3. A retired ball reads "Deleted ball" until #106's `detail(for:)` is used; the lookup is
   a closure so the switch is one line. Task 5 tests the missing-ball path.
4. Deleting the open game or session pops exactly the right routes, and a screen whose
   record vanished shows the deleted state instead of crashing. Task 3 tests the pops;
   the deleted states come from `load` throwing `.notFound` (Tasks 4 and 5).
5. A failed Next game rebuild must not allow a second `startNextGame`. Task 6 tests that
   `nextGame()` is a no-op afterwards.

**Interfaces:**
- Consumes: everything above.
- Produces (views only):
  - `HistoryStack`: `NavigationStack(path: $app.historyPath) { HistoryScreen() }` with
    `.navigationDestination(for: HistoryRoute.self)` → `SessionDetailScreen(id:)` /
    `GameDetailScreen(id:)`. `RootView`'s History tab uses it.
  - `HistoryScreen`: `HistoryList.months` in sections titled by month; rows are
    `NavigationLink(value: HistoryRoute.session(row.id)) { RecentSessionRow(row:) }`;
    `.swipeActions` Delete → `.confirmationDialog(request.title)` → `app.delete`; the
    same action as `.accessibilityAction(named: "Delete")`. Empty: "Your sessions show up
    here." and Start session (`app.isStartingSession = true`).
  - `SessionDetailScreen(id:)`: header, toolbar Edit (`app.editingSessionDetails = id`,
    sheet shows `SessionDetailsForm` with `.sharedErrorAlert(in: .sessionDetails)`),
    Resume when `resumeTarget` (`app.resume`), a section per bowler (header label from
    `AccessibilityText.bowlerHeader`), game rows `NavigationLink(value: .game(id))` with a
    compact `ScorecardStrip(scorecard:currentFrame: nil)`, swipe/VoiceOver delete.
  - `GameDetailScreen(id:)`: title, `ScorecardStrip`, leaves grid
    (`LazyVGrid(.adaptive(minimum: 64))` of `LeaveDiagramView(size: .small)` with frame
    numbers), Balls used, toolbar Edit (`app.scoring = data.editTarget`), Delete game at
    the bottom with the confirmation.
  - `SessionDetailsForm(id:)`: `SessionDetailsDraft(detail.metadata)`; date, event
    picker (plain, no remembered defaults), `SessionPlaceSection`, notes; Cancel clears
    `editingSessionDetails`; Save writes `updateMetadata` then clears it, or sets
    `app.error` and stays.
  - `RecordDeletedView(message:)`: the message and "Back to History"
    (`app.historyPath = []`). Detail screens show it when `load` throws `.notFound`.
  - Every screen reloads in `.task(id: app.revision)`.
  - Home's recent rows call `app.openSession(row.id)`.
